# Deps-Audit Allowlist — CVE/version exemptions with mandatory sunset
#
# Authoritative source: .claude/rules/deps-audit-golden-rule.md § Allowlist mechanism
#
# Format (one entry per line):
#   ECOSYSTEM|PACKAGE|VERSION-RANGE|CVE-ID|REASON|SUNSET-DATE
#
# Where:
#   ECOSYSTEM     ∈ { npm, python, rust, go }
#   PACKAGE       — exact package name as it appears in the manifest
#   VERSION-RANGE — semver range matching the affected version(s) (e.g., ^4.17.20)
#   CVE-ID        — CVE-YYYY-NNNN or GHSA-xxxx-xxxx-xxxx (the canonical advisory ID)
#   REASON        — specific rationale; "WIP" / "TODO" / "investigating" are NOT accepted
#   SUNSET-DATE   — YYYY-MM-DD; MUST be:
#                     ≤ 30 days from entry creation for CRITICAL
#                     ≤ 60 days for HIGH
#                     ≤ 90 days for MEDIUM / LOW
#
# Behavior:
#   - Lines starting with `#` and blank lines are skipped.
#   - Active entry (today ≤ SUNSET-DATE): /deps-audit downgrades the finding by one severity level.
#   - Expired entry (today > SUNSET-DATE): IGNORED; CVE re-fires at full severity.
#   - /deps-audit MUST list expired entries in the report's "Allowlist hits — expired" subsection.
#
# Adding/modifying entries:
#   - Adding requires inline rationale in the plan that introduced the dep.
#   - Modifying SUNSET-DATE extends the grace period — commit message MUST explain why.
#   - Removing an entry is the normal lifecycle (CVE was patched OR sunset reached).
#
# Examples (commented — uncomment + adapt when needed):
#
# npm|lodash|^4.17.20|CVE-2021-23337|patch upgrade requires regression test rerun; scheduled Q3 2026|2026-08-01
# python|pyyaml|<6.0|CVE-2020-14343|removing pyyaml requires refactor of config loader (planned T2.4 of plan X)|2026-06-15
#

# Active entries — adapters-openrouter-local-embedder cycle (plan v1.1, /deps-audit re-gate at T1.1 2026-06-01)
# Root cause: protobufjs<=7.5.7 has 1 CRITICAL + 4 HIGH + 3 MODERATE advisories. Chain: @xenova/transformers ^2.17.0 -> onnxruntime-web@1.14.0 (pinned exact by Xenova) -> onnx-proto -> protobufjs.
# Risk-envelope analysis (per /implement iter 4 halt report): the protobufjs RCE + DoS + prototype-pollution advisories all require attacker-controlled input reaching the parser. In our use case, protobufjs ONLY parses the ONNX model .onnx file downloaded from huggingface.co/Xenova/all-MiniLM-L6-v2 CDN at warmup (one-time, signed manifest). Chat-text-from-user → tokenizer → ONNX inference path does NOT route through the protobuf parser at runtime. Vector of attack reduces to CDN compromise or MitM of model download — low for local-dev demo, would be medium-high for production exposure.
# Demo scope: TheMemory is pre-release per CLAUDE.md § Roadmap; the chat-with-memory demo is the dogfood evidence surface, NOT production. dogfood-golden-rule.md gates any production-ready claim, so the v1.0 milestone cannot ship while these allowlist entries are active — that creates pressure to remove them within the sunset window.
# Tracking: upstream issue at https://github.com/xenova/transformers.js/issues (Xenova v3 line is in progress and is expected to bump onnxruntime-web ≥ 1.18 which uses protobufjs ≥ 7.5.8). Re-audit at sunset to verify upstream fix or escalate (replace dep with fastembed-js or Python sidecar via Rule 9 re-evaluation).
