### Why this matters NOW (motivation per retrospective 2026-05-25)

1. **`/to-plan` Step 0 patterns-skill discovery only works for domains where `cycle-discover` already ran AND produced a `*-patterns` skill.** Today there are ZERO such skills. Every plan ships unaware of canonical pattern guidance.
2. **`/plan-confidence` `architecture_compliance` is binary** — it checks if a plan CITES SOLID/DRY/KISS/YAGNI but cannot answer "for THIS plan specifically, is Strategy pattern the canonical choice here? Are we reinventing Factory? Is Repository missing?". The signal is rule-name citation, not pattern-fit analysis.
3. **Risk evidence:** the v0-3-agent-tools-mcp plan adopted the Strategy pattern for dispatch handlers without explicit ADR naming it as Strategy. discover-web-v0-1 plan uses Phase-A/Phase-B halt-loop without ADR naming this as Pipeline pattern. 4. **Inquebrável Rule 9 (Não Reinvente):** the rule is currently enforced for DEPENDENCIES (via `/deps-audit`). It is NOT enforced for DESIGN — a plan can perfectly use Rule-9-approved libs while accidentally inventing a half-broken pseudo-Factory. This cycle closes that gap at the DESIGN level.

## ADRs

### D1 — Cycle independence: paralelo-opcional, NOT modifying cycle-plan v1.x

**Decision:** `cycle-design-patterns` is an INDEPENDENT cycle. Its outputs are consumable artifacts (pattern-audits at `.claude/knowledge-base/design-patterns/blueprints/`) that `/to-plan` Step 0 MAY reference, but it does NOT extend the `cycle-plan` chain (`/to-plan` → `/edge-case-plan` → `/deps-audit` → `/plan-confidence` stays unchanged).

**Alternatives considered:**
- (a) Insert `/design-pattern-execute` as a new mandatory phase in cycle-plan v1.2 — between `/edge-case-plan` and `/deps-audit`. REJECTED: violates KISS for simple plans (trivial bug-fix plans don't need GoF audit); adds ~80-200k tokens to EVERY plan invocation; breaks v1.1 contract.
- (b) Make `/design-pattern-execute` a soft cap in `/plan-confidence` (advisory only) — REJECTED: pollutes plan-confidence's deterministic Python-only architecture with halt-loop dependency; gate signals get mixed.

**Rationale:** mirrors `cycle-discover`'s relationship to `cycle-plan` — discover OUTPUTS feed plan INPUTS (via `*-patterns` skills) without forcing every plan to invoke discover. Same model here.

**Consequences:** Pattern audits are OPT-IN, invoked by the human OR by a plan-author who decides the plan's domain warrants it. Cost is paid only when needed. Cycle-plan v1.x remains unchanged; v1.2 (if drafted later) might add an optional reference, but this plan does NOT touch it.

### D2 — Output location: `.claude/knowledge-base/design-patterns/`, NOT `.claude/skills/*-patterns/`

**Decision:** Pattern-audit blueprints live at `.claude/knowledge-base/design-patterns/blueprints/{target-plan-slug}-patterns-audit.md`. They are NOT skills — they are AUDIT REPORTS specific to one target plan.

**Alternatives considered:**
- (a) Emit a `{target-plan-slug}-patterns/` skill at `.claude/skills/` following `cycle-discover`'s convention — REJECTED: patterns-skill is meant to be REUSABLE across many future plans (one skill per investigated domain like "pgvector-schema-patterns"). A pattern AUDIT is plan-specific (one audit per target plan, not reused).
- (b) Inline the audit into the target plan's markdown — REJECTED: pollutes the plan's source of truth; audit can be re-run independently when patterns evolve.

**Rationale:** semantic clarity. The cycle produces audit reports, not reusable skills. `.claude/knowledge-base/` is the established home for cycle outputs (plans, blueprints, reviews, audits — see existing structure).

**Consequences:** New top-level directory `.claude/knowledge-base/design-patterns/` with sub-dirs `plans/`, `blueprints/`, `reviews/`, `snapshots/`. `/to-plan` Step 0 gets an additional scan target (Sub-goal 8). The `*-patterns` skill convention from `cycle-discover` is preserved and untouched.

### D3 — 5 coverage corners (gof, ddd, architectural, cloud, language_idiomatic) — NOT 3 or 7

**Decision:** The audit covers exactly 5 corners; each declared as required OR `<!-- DEFER-CORNER: {corner} | {reason} -->` per cycle-discover.md v1.1 convention.

**Alternatives considered:**
- (a) 3 corners (gof + ddd + architectural only) — REJECTED: misses cloud-native patterns (Sidecar, Circuit Breaker, Saga) increasingly relevant for TheMemory's `src/cloud/` future + misses language-idiomatic patterns (TS branded types, exhaustive switches) that are KISS wins.
- (b) 7 corners (add reactive + functional + concurrency) — REJECTED: reactive + functional + concurrency are themselves cross-cutting (functional patterns appear in GoF Strategy = functional alt, Observer = reactive seed); over-segmentation. 5 corners are MECE enough.

**Rationale:** mirrors cycle-discover's 4 → 5 corner evolution (v1.1 added `prior_art` deliberately). 5 is the right granularity; matches typical book-chapter divisions (GoF Vol 1, Fowler PEAA, Evans DDD, cloud-design-patterns.com, language idiom guides).

**Consequences:** Each pattern-audit blueprint MUST have 5 corner sections (or explicit DEFER markers). `check_pattern_coverage.py` enforces. Adding a 6th corner later requires ADR + golden rule extension (mirrors how discover-web added 5th to cycle-discover).

### D4 — Hard dependency on `discover-web-v0-1` SHIPPED before `/design-pattern-execute` /implement

**Decision:** This plan's `/implement` phase depends on `discover-web-v0-1`'s plan being SHIPPED first. Specifically, the halt-loop in `/design-pattern-execute` invokes `WebSearch` + `WebFetch` + snapshot-write per the 7-step protocol from `cycle-discover.md v1.1`. Without that infra wired, every citation in a pattern audit would be fabricated (model recall) — Inquebrável Rule 3 violation.

**Alternatives considered:**
- (a) Skip web research; cite from training-data only — REJECTED: same fabrication risk that motivated discover-web in the first place. Cycle-discover.md v1.1 Anti-pattern #10 ("NEVER fabricate a URL from training-data recall") applies symmetrically here.
- (b) Bundle a small local pattern-catalog (markdown files with verified GoF/DDD/etc summaries) in the skill itself — REJECTED: maintenance debt; bundled catalog drifts; would need its own versioning + rotation policy. WebSearch + snapshot is the existing solution.

**Rationale:** Inquebrável Rule 9 (Não Reinvente) — discover-web already solves the citation-with-snapshot problem. Reuse.

**Consequences:** `cycle-design-patterns-v0-1`'s Phase 0 audit MUST verify `discover-web-v0-1` is committed AND `check_reference_citations.py` handles URL citations (NOT just `referencia/`). If not, this plan's `/implement` halts. Project ordering invariant locked: discover-web FIRST, then cycle-design-patterns.

### D5 — 5-verdict classification rubric (APPLIED_CORRECTLY / MISAPPLIED / MISSING_RECOMMENDED / OVER_ENGINEERED / NOT_APPLICABLE)

**Decision:** Each pattern analyzed receives EXACTLY one of 5 verdicts. The rubric is locked at this granularity for v0.1.

**Alternatives considered:**
- (a) 3 verdicts (APPLIED / MISSING / OVER_ENGINEERED) — REJECTED: collapses MISAPPLIED into APPLIED (false positive, hides design defects) AND loses NOT_APPLICABLE distinction (forces analyst to apply patterns where they don't fit, polluting output).
- (b) 7 verdicts (split MISAPPLIED into WRONG_CONTEXT + WRONG_INTENT, split MISSING_RECOMMENDED into MISSING_HARD + MISSING_NICE_TO_HAVE) — REJECTED: false precision; reviewers can't reliably distinguish nuances; 5 verdicts already cover 95% of real findings.

**Rationale:** matches the granularity used in real-world architecture-review literature (Bass/Clements/Kazman "Software Architecture in Practice" uses similar 5-verdict style for ATAM reviews).

**Consequences:** Each finding in a pattern-audit blueprint MUST declare exactly one verdict. `check_pattern_classifications.py` enforces verdict-vocabulary (rejects free-form labels). Aggregate verdict (SHIPPABLE/etc) depends on counts: hard cap fires when ≥ N misapplied patterns OR ≥ N missing-recommended without ADR justification.

### D6 — Halt-loop reuses ralph-loop (file-referenced pattern), NOT custom loop engine

**Decision:** `/design-pattern-execute` invokes `ralph-loop:ralph-loop` via the file-referenced pattern per `loop-engine-convention.md § How to invoke ralph-loop:ralph-loop safely`. Halt-loop emits `<promise>PATTERN_AUDIT_COMPLETE</promise>` when (a) every pattern in the shortlist has a verdict + citation, (b) every citation has a valid snapshot per discover-web infra.

**Alternatives considered:**
- (a) Custom Python halt-loop with own restart logic — REJECTED: violates Rule 9 (ralph-loop already exists and is proven across discover/improve/implement cycles).
- (b) Single-shot LLM invocation without iteration — REJECTED: pattern shortlist of 5-15 entries × WebSearch + WebFetch + snapshot-write + classify per pattern exceeds single-context budget; iteration is necessary.

**Rationale:** consistency across the ecosystem — every halt-loop in the project uses ralph-loop. Operators only need to learn one halt-loop API.

**Consequences:** `/design-pattern-execute` SKILL.md invokes ralph-loop with `--completion-promise 'PATTERN_AUDIT_COMPLETE' --max-iterations N` per cycle-discover convention. Driver prompt lives at `.claude/halt-loop-prompts/design-pattern-execute-{slug}.md` (gitignored per existing pattern). Same shell-safety constraint applies (positional arg must be shell-safe per loop-engine-convention).

### D7 — Test fixtures use REAL plans from `.claude/knowledge-base/plans/`, NOT synthetic

**Decision:** Golden-fixture tests reference actual shipped plans (`v0-3-agent-tools-mcp-plan.md`, `discover-web-v0-1-plan.md`) for cross-validation; synthetic-only fixtures are deferred.

**Alternatives considered:**
- (a) Synthetic plans (minimal markdown fabricated for tests) — REJECTED: doesn't catch real-world plan structures; loses regression signal when plan template evolves.
- (b) Both real + synthetic — DEFERRED to v0.2; v0.1 ships with real plans only to keep scope bounded.

**Rationale:** "eat your own cooking" — the cycle MUST be testable against the project's real plan corpus.

**Consequences:** Tests at `.claude/skills/design-pattern-confidence/tests/test_*.py` import `v0-3-agent-tools-mcp` + `discover-web-v0-1` plan paths. If either plan is moved (e.g., to `plans/completed/`), tests update + commit must coordinate per `audit-trail-rotation.md § active vs completed`.

### D8 — `cloud` corner is OPT-IN per target plan declaration; defaults to DEFER

**Decision:** When a target plan does NOT touch `src/cloud/` OR multi-region OR managed-service surfaces, the `/design-pattern-plan` declares `<!-- DEFER-CORNER: cloud | target plan is local-runtime / refactor / docs only -->` and the `cloud` corner is skipped without penalty. When a target plan DOES touch cloud surfaces, `cloud` is mandatory.

**Alternatives considered:**
- (a) Always-on cloud corner — REJECTED: forces every plan (including markdown-only refactors like discover-web-v0-1) to evaluate Saga/Sidecar/Circuit-Breaker fit, polluting outputs with NOT_APPLICABLE noise.
- (b) Always-off cloud corner — REJECTED: critical for future TheoCloud-bound plans (Roadmap Item 7 — `src/cloud/` lands at v0.5).

**Rationale:** mirrors how `cycle-discover` v1.1's `prior_art` corner allows DEFER with documented rationale.

**Consequences:** `/design-pattern-plan` template includes a `cloud_applicable: yes/no/defer-with-rationale` field. `check_pattern_coverage.py` accepts DEFER-CORNER for `cloud` without emitting `empty_corner_cloud` cap when properly justified.
