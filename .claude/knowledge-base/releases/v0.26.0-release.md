## What shipped

- **Security (#82):** MCP tool surface now enforces per-tenant workspace isolation — the
  cross-tenant data leak is closed. Bearer gate resolves a `Principal` and binds
  `Memory.withWorkspace(workspaceId)` at every tool memory-access site (the new
  `workspaceScopedMemory` seam), fed by an auth-trusted `ScopedContext.workspaceId`,
  fail-closed (null/blank→401, withWorkspace-absent→typed error, backend→503,
  verify-only→401).
- **Added:** native streamable-HTTP MCP transport binds the per-request user scope from
  `X-Theo-User-Id` (the integrated MCP-Gateway path the #82 fix secures) + README TLS docs.
- **CI:** `docker-publish` self-hosted runner + Trivy pin + secrets-context-in-`if:` fix.

## Version-correction note (honest disclosure, Rule 3)

The `/release` skill initially computed **0.11.0** because `git describe --tags` read STALE
LOCAL tags (only up to v0.10.0 were fetched locally; v0.11.0..v0.25.0 live on `main` merge
commits not reachable from `develop`'s HEAD). The PR was titled `release: 0.11.0` and the
CHANGELOG section was promoted to `[0.11.0]` before the collision was caught (v0.11.0 was
already published 2026-06-20; the true latest is v0.25.0). **Recovery (owner-approved):**
tagged the merge commit as the correct next version **v0.26.0**, published the v0.26.0
GitHub release, and corrected the CHANGELOG header `[0.11.0]` → `[0.26.0]` on `develop`
(commit `68fedbc`). The merged code on `main` is correct; only the version number was wrong.

**Known cosmetic debt:** `main`'s CHANGELOG still carries the `## [0.11.0] - 2026-06-30`
header for this release's content (the merge commit predates the `68fedbc` correction). It
will be corrected on `main` when `develop`'s fix reaches it via the next release PR.
**Process follow-up:** the release skill's `compute_next_version` should consult
`git fetch --tags` + the highest tag across all refs (not the develop-reachable
`git describe`), so a divergent develop/main tag topology cannot mis-compute the version.
