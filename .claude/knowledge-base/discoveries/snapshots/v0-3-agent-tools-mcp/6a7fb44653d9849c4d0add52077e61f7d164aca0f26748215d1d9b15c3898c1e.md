# Tools (MCP 2025-11-25)

MCP allows servers to expose tools that can be invoked by language models. Tools enable models to interact with external systems. Each tool is uniquely identified by a name and includes metadata describing its schema.

## User Interaction Model

Tools in MCP are **model-controlled** — the language model can discover and invoke tools automatically. However, protocol does not mandate any specific user interaction model.

For trust & safety, there SHOULD always be a human in the loop with the ability to deny tool invocations. Applications SHOULD provide UI that makes clear which tools are exposed; insert visual indicators when tools are invoked; present confirmation prompts.

## Capabilities

Servers that support tools MUST declare the `tools` capability:
```json
{
  "capabilities": {
    "tools": {
      "listChanged": true
    }
  }
}
```
`listChanged` indicates whether the server will emit notifications when the list of available tools changes.

## Protocol Messages

### Listing Tools — tools/list

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": { "cursor": "optional-cursor-value" }
}
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [
      {
        "name": "get_weather",
        "title": "Weather Information Provider",
        "description": "Get current weather information for a location",
        "inputSchema": {
          "type": "object",
          "properties": {
            "location": { "type": "string", "description": "City name or zip code" }
          },
          "required": ["location"]
        },
        "icons": [{ "src": "...", "mimeType": "image/png", "sizes": ["48x48"] }],
        "execution": { "taskSupport": "optional" }
      }
    ],
    "nextCursor": "next-page-cursor"
  }
}
```

### Calling Tools — tools/call

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": { "name": "get_weather", "arguments": { "location": "New York" } }
}
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{ "type": "text", "text": "Current weather in New York:\n..." }],
    "isError": false
  }
}
```

### List Changed Notification
```json
{ "jsonrpc": "2.0", "method": "notifications/tools/list_changed" }
```

## Data Types

### Tool
- `name`: Unique identifier
- `title`: Optional human-readable name
- `description`: Human-readable description
- `icons`: Optional array of icons
- `inputSchema`: JSON Schema (2020-12 default), MUST be valid (not null). For no-params: `{ "type": "object", "additionalProperties": false }` (recommended).
- `outputSchema`: Optional JSON Schema for output validation
- `annotations`: Optional behavior descriptors (clients MUST consider untrusted unless from trusted servers)
- `execution`: Optional, with `taskSupport` ∈ {`forbidden` (default), `optional`, `required`}

### Tool Name Constraints
- 1-128 chars (SHOULD)
- Case-sensitive (SHOULD)
- Allowed chars: A-Z, a-z, 0-9, _, -, .
- SHOULD NOT contain spaces, commas, or other special characters
- SHOULD be unique within a server
- Examples: getUser, DATA_EXPORT_v2, admin.tools.list

### Tool Result Content Types
- **Text Content**: `{ "type": "text", "text": "..." }`
- **Image Content**: `{ "type": "image", "data": "base64...", "mimeType": "image/png", "annotations": {...} }`
- **Audio Content**: `{ "type": "audio", "data": "base64...", "mimeType": "audio/wav" }`
- **Resource Links**: `{ "type": "resource_link", "uri": "file:///...", "name": "...", "description": "...", "mimeType": "..." }`
- **Embedded Resources**: `{ "type": "resource", "resource": { "uri": "...", "mimeType": "...", "text": "..." } }`

### Structured Content
Returned as JSON object in `structuredContent` field of result. For backwards compatibility, tool returning structured content SHOULD also return serialized JSON in a TextContent block. If output schema is provided: servers MUST conform; clients SHOULD validate.

## Error Handling — TWO MECHANISMS

1. **Protocol Errors** (JSON-RPC error object): unknown tools, malformed requests, server errors. Less likely models can self-correct.
   ```json
   { "jsonrpc": "2.0", "id": 3, "error": { "code": -32602, "message": "Unknown tool: invalid_tool_name" } }
   ```

2. **Tool Execution Errors** (`isError: true` in result): API failures, input validation, business logic errors. Actionable for LLM self-correction.
   ```json
   { "jsonrpc": "2.0", "id": 4, "result": {
       "content": [{ "type": "text", "text": "Invalid departure date: must be in the future." }],
       "isError": true
   }}
   ```

Clients SHOULD provide tool execution errors to language models for self-correction.

## Security Considerations

Servers MUST: validate all tool inputs; implement access controls; rate limit invocations; sanitize outputs.

Clients SHOULD: prompt for user confirmation on sensitive operations; show tool inputs to user before calling server; validate tool results before passing to LLM; implement timeouts; log tool usage.
