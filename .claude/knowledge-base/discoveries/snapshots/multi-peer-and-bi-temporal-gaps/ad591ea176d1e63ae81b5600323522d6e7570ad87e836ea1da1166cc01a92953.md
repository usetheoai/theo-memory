## Bi-temporal field declarations (Pydantic model)

```python
created_at: datetime
# (declared on base class for ALL edges/nodes; system-time of DB row creation)

# On EntityEdge (the fact-carrying edge):
expired_at: datetime | None = Field(
    default=None, description='datetime of when the node was invalidated'
)
valid_at: datetime | None = Field(
    default=None, description='datetime of when the fact became true'
)
invalid_at: datetime | None = Field(
    default=None, description='datetime of when the fact stopped being true'
)
# reference_time: datetime — also present on the model
```

## DB serialization (`get_data_dict` returns):
```python
{
    'fact_embedding': self.fact_embedding,
    'episodes': self.episodes,
    'created_at': self.created_at,
    'expired_at': self.expired_at,
    'valid_at': self.valid_at,
    'invalid_at': self.invalid_at,
    'reference_time': self.reference_time,
}
```

## DB deserialization (`from_record`):
```python
created_at=parse_db_date(record['created_at']),
expired_at=parse_db_date(record['expired_at']),
valid_at=parse_db_date(record['valid_at']),
invalid_at=parse_db_date(record['invalid_at']),
reference_time=parse_db_date(record.get('reference_time')),
```

## Classification
**TRI-TEMPORAL** (NOT bi-temporal):
- `created_at` — system time (DB row birth)
- `valid_at` / `invalid_at` — business-time validity window for the fact
- `expired_at` — semantically distinct from `invalid_at` (the docstring says "when the node was invalidated" — refers to the underlying entity-node, not the fact-edge)
- `reference_time` — additional temporal axis

This is a fuller bi-temporal model than the textbook (system-time + valid-time) — Graphiti adds a node-invalidation axis on top.
