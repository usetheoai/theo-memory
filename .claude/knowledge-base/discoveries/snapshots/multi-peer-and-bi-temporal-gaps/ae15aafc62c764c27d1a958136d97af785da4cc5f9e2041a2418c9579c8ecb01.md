# Honcho Project Extract

## (a) Purpose & Marketing Tagline

**Purpose:** "Honcho is memory infrastructure for building stateful agents that understand changing people, agents, groups, projects, and ideas over time."

**Tagline:** "Store messages and events, let Honcho reason in the background, then query peer representations, session context, search results, or natural-language insights from any model or framework."

## (b) Theory-of-Mind & Multi-Peer Model

The documentation emphasizes a **peer-centric architecture**:

- "Honcho organises everything around **peers** — humans and AI agents alike are first-class entities."
- "The peer model enables: Multi-participant sessions with mixed human and AI agents; Configurable observation settings (which peers observe which others); Flexible identity management"
- **Multi-peer perspective explicitly stated:** "Models what one peer knows about another when configured."
- **Collections keyed by observer/observed pairs:** "Collections are keyed by `(observer, observed)` peer pairs — the same mechanism powers self-representation (`observer == observed`) and cross-peer modelling (peer X's understanding of peer Y)."

## (d) Public API Verbs/Endpoints

Core methods exposed:
- `session.add_messages(...)` — store interactions
- `peer.chat(...)` — query about peer knowledge
- `peer.search(...)`, `session.search(...)` — hybrid search
- `peer.representation(...)`, `session.representation(...)` — static snapshots
- `session.context(...)` — prompt-ready bundling
- `honcho.queue_status(...)` — monitor background processing
