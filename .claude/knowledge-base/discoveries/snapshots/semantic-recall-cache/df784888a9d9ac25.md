## Verbatim findings (from WebFetch summary)

### Default similarity threshold
NOT documented as a project default. README shows `Config(similarity_threshold=0.2)` as a COMMENTED-OUT example — explicitly customizable. (Note: in GPTCache nomenclature, `0.2` may represent DISTANCE not similarity — lower distance ≈ closer match.)

### Default cache invalidation strategy
NOT documented as default. README references "Eviction Policy" supporting:
- LRU eviction policy
- FIFO eviction policy
- LFU eviction policy
- RR eviction policy (Random Replacement)

No TTL-based default mentioned. No write-triggered scope invalidation documented.

### Default backend
NOT explicitly designated. Multiple options:
- Cache Storage: SQLite (universal interface)
- Vector Store: Milvus, Zilliz Cloud, FAISS

Quickstart example uses: `"sqlite,faiss"` combo.

### Observability metrics
GPTCache measures internally:
- Hit Ratio
- Latency
- Recall

NO documented Prometheus or OpenTelemetry integration.

### Architecture components (README "GPTCache Struct" diagram)
1. **LLM Adapter** — interfaces with LLM providers
2. **Multimodal Adapter** — multi-modal request handling
3. **Embedding Generator** — converts prompts to vectors
4. **Cache Storage** — stores LLM responses
5. **Vector Store** — finds K most similar requests by embedding
6. **Cache Manager** — orchestrates the cache lifecycle
7. **Similarity Evaluator** — applies the similarity threshold

Embedchain's `cache.py` at `.claude/knowledge-base/references/mem0/embedchain/embedchain/cache.py:25-27`:

def gptcache_data_manager(vector_dimension):
    return get_data_manager(cache_base="sqlite", vector_base="chromadb", max_size=1000, eviction="LRU")

This is empirical consumer evidence: real users configure GPTCache with `sqlite + chromadb + max_size=1000 + LRU`. ChromaDB is a documented alternative vector backend (not Milvus). This suggests:
- **Default-in-practice backend** = `sqlite + chromadb` (NOT Milvus despite Milvus being mentioned first in GPTCache docs)
- **Default-in-practice eviction** = `LRU` (most common consumer choice)
- **Default-in-practice capacity** = `max_size=1000`

## Honest disclosure

The README does NOT provide a load-bearing default threshold or invalidation strategy. The threshold (`0.2` in example) is shown as a customizable seed, not a "use this" recommendation. This is a HONEST gap — GPTCache leaves these decisions to the consumer.

For TheMemory v1.5 design: this means GPTCache is NOT a source of "lock the threshold at 0.X" guidance. Consumer empiricism (embedchain's choices, LangChain's choices — Q7) becomes more load-bearing than GPTCache itself.
