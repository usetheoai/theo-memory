# Cognee — ECL Pipeline + Ontology-Enhanced Knowledge Graph Memory

## Architecture (verbatim claims)

- **Two-layer memory:** Session memory (short-term working) + Permanent memory (long-term knowledge artifacts: user data + interaction traces + external docs + derived relationships).
- **Hybrid graph + vector:** "every node in the graph has a corresponding embedding, so you can move between semantic similarity and relational traversal without losing coherence."

## Episodic→Semantic abstraction (explicit)

"Cognee specifically performs episodic-to-semantic abstraction: similar sessions tend to share underlying structure even when explicit details differ. Cognee clusters those repeated paths into episodic groups and then compresses them into semantic abstractions — reusable representations of this kind of situation rather than one-off instances."

This is EXPLICITLY the v0.7 problem statement. Cognees mechanism: cluster sessions → compress to abstractions.

## ECL Pipeline (Extract — Cognify — Load)

"raw inputs move into normalized documents, which then become a knowledge graph with embeddings, and finally lead to searchable answers."

## Ontology integration (Cognees signature feature)

"Cognee uses Instructor-powered structured output to generate a KnowledgeGraph (a list of typed Node and Edge objects) from each document chunk. Then the RDFLibOntologyResolver parses your OWL file and builds two in-memory lookup dictionaries: one for classes, one for individuals."

Optional — if no ontology, builds graph from data. If OWL ontology provided, validates extracted nodes against it.

## Foundational citation

"Cognees cognitive architecture is grounded in academic research — specifically defining cognitive architecture based on an impactful paper (CoALA)" — they cite the SAME paper we cite (Sumers 2023, Q7).

## v0.7 implications + honest gap audit

Cognee claims episodic→semantic abstraction via clustering + compression. Gaps in blog:
- Cluster algorithm not specified (DBSCAN? k-means on embeddings? LLM-judged?)
- Compression prompt not shown
- Provenance schema not documented in blog ("which sessions contributed to this abstraction?")
- Ontology integration adds complexity — not clear if its required or optional for the core memory architecture

**Differentiation:** v0.7 against Cognee:
1. SHIP the clustering algorithm transparently (HNSW cosine cluster threshold? K-means? LLM-judged? document the choice + ADR)
2. SHIP the compression prompt verbatim in the SDK
3. PROVENANCE: explicit `derived_from: [sessionId]` on every compressed abstraction
4. NO ontology dependency by default (avoid Cognees poly-store complexity); ontology is opt-in for v1.4 per CLAUDE.md Roadmap Item 15
