# Milestone M4 — Accountable-forgetting governance + surfaces (retention · MCP · dashboard)

## Objective (from ROADMAP.md)

Ship the governance + surfaces layer for the "accountable forgetting" audit log: a
per-tenant retention sweep that bounds the `recall_traces` table, a per-workspace
fail-closed opt-out, and an MCP `explain_recall` tool so an agent can ask WHY a recall
dropped candidates. (The dashboard surface is cross-repo in theo-cloud and does NOT gate
this checkbox per the milestone DoD.)

## Definition of done — validated

- [x] `RecallTraceRetentionPolicy` DIP + `PgRecallTraceRetention.sweep` — age-based, race-safe
  age-based `DELETE` (SERIALIZABLE + 40001 retry). Proven real-40001 by two concurrent sweeps.
- [x] Per-workspace fail-closed opt-out — `disabledWorkspaces`, checked in-memory at the write
  gate (no per-recall DB read), operator-reachable via `THEOMEM_RECALL_TRACE_DISABLED_WORKSPACES`.
- [x] `croner`-driven retention cron wired at the server composition root; `recall_trace_swept`
  OTel counter; validated window (fail-fast, never a full-wipe); drains in-flight sweep on shutdown.
- [x] MCP `explain_recall` tool — workspace from auth-trusted scope (CWE-441 safe), reuses S2
  `getByRecallId`, projected DTO (no internal-field leak).
- [x] Benchmark evidence recorded: sweep 335,276±40,449 rows/sec; trace write 4.26±0.59 ms/recall.
