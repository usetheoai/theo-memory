# Release v0.27.0 — BLOCKED on image push (package permission)

**Date:** 2026-06-30
**Verdict:** PR merged (#87) + tag `v0.27.0` cut on `38d0c07`; CHANGELOG promoted.
**IMAGE_STATUS:** **FAILED** — the signed-image push 403s. NOT a code issue.

## What happened
The converged `publish.yml` → reusable `theo/build-publish.yml` ran on v0.27.0 (run 28462518384).
Trivy gate passed (#86 fixed). The **Build + push (SBOM + SLSA mode=max)** step failed:

```
ERROR: failed to solve: failed to fetch anonymous token:
GET https://ghcr.io/token?scope=repository:usetheodev/themory:pull,push : 403 Forbidden
```

## Root cause (infra, not code)
The SAME reusable signed + pushed `theo-mcp-gateway:0.29.0`, `theo-cloud:0.16.0`, and
`theo-dashboard:0.16.0` cleanly. Only the **`themory` GHCR package** 403s — it does not grant the
`theo-memory` repo's Actions `GITHUB_TOKEN` push (the other 3 packages do, because they were first
created by their own repos' Actions). buildx falls back to an anonymous token → 403 on the
attestation push.

## Fix (one-time, package admin — needs the usetheodev account)
1. https://github.com/users/usetheodev/packages/container/themory/settings
2. **Manage Actions access** → **Add Repository** → `theo-memory` → Role: **Write**
   (and confirm the package's visibility / repo link).
3. Backfill the image: `gh run rerun 28462518384 -R usetheodev/theo-memory --failed`
   (re-runs the failed v0.27.0 publish; trivy+sign+verify will then complete).

## Note
The sign+verify MECHANISM is proven live on 3 packages (theo-mcp-gateway, theo-cloud,
theo-dashboard). themory's blocker is purely the package-access grant above.
