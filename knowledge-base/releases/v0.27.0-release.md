**IMAGE_STATUS:** **FAILED** at the signed-image attestation push. NOT a package-permission issue,
NOT theo-memory code — a bug in the shared reusable's `trivy: true` + `sign` combination.

## Symptom
publish.yml (run 28462518384) — Trivy gate PASSED (#86 fixed). The `Build + push (SBOM + SLSA
mode=max)` step failed:
`failed to fetch anonymous token: .../usetheodev/themory:pull,push : 403 Forbidden`.

## Root cause (isolated by elimination)
- Package permission is FINE: `themory:develop` (sign=false, no attestations) pushes succeed — 3
  green develop runs. You cannot push without Write, so the `theo-memory` repo HAS write to the
  package.
- `theo-mcp-gateway:0.29.0`, `theo-cloud:0.16.0`, `theo-dashboard:0.16.0` all sign+push cleanly via
  the SAME reusable with `sign: true` (mode=max) — but `trivy: false` (single build).
- The ONLY repo with `trivy: true` is themory, and ONLY its tag build (trivy double-build + mode=max
  attestation push) 403s. So the bug is in the reusable's `trivy + sign` path: the post-build
  attestation push loses registry auth (goes anonymous) after the Trivy "build-for-scan" step.

## Fix (in the reusable `theo/build-publish.yml`, NOT here)
Make the `trivy: true` path not disturb the builder's registry auth for the subsequent
attestation push (candidates: isolate the scan build's cache scope / exporter; or do the
push-build's provenance with explicit auth). Then backfill:
`gh run rerun 28462518384 -R usetheodev/theo-memory --failed`.
