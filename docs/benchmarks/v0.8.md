### Cell semantics

- **Smoke ✅** — the e2e test (gated under `npm run test:benchmark`) runs
  the adapter against a small hand-authored fixture (3 questions for
  LongMemEval, 2 for LoCoMo, 2 for DMR) and verifies the runner produces
  a structurally complete RunReport (per-question F1 / judge label /
  latencyMs / costUsd + aggregate P95 + means). BLEU is **deferred** via
  `Drift-T1.1-1` (ADR D1 of v0-8-fixes-cycle-1) — `natural@8.x` dropped
  BLEU; F1 + Exact Match cover the lexical metric niche; LLM-judge covers
  semantic. This proves the wiring works end-to-end without spending the
  30-50 minute cost of a full run.
- **Deferred — Drift-T6.x-1** — the adapter declares the
  `BenchmarkAdapter` Protocol from `src/core/dip/benchmark-adapter.ts`
  via a VendorClient DIP interface, but the real vendor SDK
  (`mem0ai`, `@getzep/zep-cloud`, Letta REST) is not yet wired. Real-SDK
  integration is the responsibility of a follow-up cycle so that each
  vendor adapter goes through its own `/deps-audit` for SDK CVE
  surface.

### Full TheMemory runs (gated)

The smoke cells above validate the wiring; the full 500-question
LongMemEval run (per `xiaowu0162/longmemeval-cleaned` upstream) +
full LoCoMo + DMR runs require:

- `BENCH_RUN=full` environment variable
- A valid `OPENAI_API_KEY`
- ~30-50 minute wall-clock per cell

They are gated behind `describe.skipIf` in the e2e benchmark suite.
Expected publication path post-CI run: `docs/benchmarks/v0.8-raw-results/`.

## Headline numbers

None published. The smoke fixtures exercise wiring, not retrieval
quality, so reporting headline accuracy/recall numbers from them
would be benchmark theater (Inquebrável Rule 3).

When the full TheMemory cells land via CI BENCH_RUN=full, they will
appear here with the methodology + raw-data trail. When the vendor
cells land via the follow-up cycle, they will appear here too. Until
then, the honest published state is: **smoke validated, full
reproduction in progress.**
