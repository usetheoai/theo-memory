### Added

- **v0.6 — `memory.skills(repoId)` code-as-skill procedural memory layer** (Roadmap Item 8; THE GOAL TEST anchor `tests/integration/skills/consolidate-two-skills.test.ts`): new public surface for code-agent skill persistence with `derived_from` provenance + supersession-based versioning. **API:** `memory.skills(repoId)` returns `ScopedSkillMemory` with 4 verbs — `add(skill: SkillDraft)` writes `kind='skill'` rows with code-as-skill payload, `recall(query, options?)` semantic search with `onlySkills` + `includeSuperseded` filters (default `false` — returns tip-of-chain), `consolidate(options?)` runs the 4-phase Orient → Gather → Consolidate → Report orchestrator producing one derived skill per cluster of semantically-equivalent sources, `forget(skillId)` hard-deletes via store. **Architecture:** REUSE of the v0.4a `executeReflection` + `validateProvenance` + `insertDerivedSkill` chain (no sibling chain per plan ADR D1); additive `kind='skill'` discriminator + `superseded_by` self-FK + 4 new memories columns (code/description/code_language) shipped via Drizzle migration `0002_skill_columns.sql` (EC-1 absorption: CHECK constraint name `memories_kind_derived_from_check` cited verbatim in DROP+ADD pair). **Atomicity** (EC-2 absorption): `insertDerivedSkillAtomic(args, sourceIds)` on PgvectorStore wraps INSERT + UPDATE in a single BEGIN/COMMIT — sources are marked `superseded_by` atomically with the derived skill insert. In-memory store runs the pair sequentially as documented best-effort (tests/dev only). **Filter parity** (EC-3 absorption): `Filters` gains `kind` + `excludeSuperseded`; `RecallOptions` + `GetAllOptions` gain `onlySkills` + `includeSuperseded`; Orient phase calls with both options for consistent semantics across recall and getAll. **Scope** (EC-4 absorption): new `RepoScope` ({kind:'repo', repoId}) on the Scope union; 4 switch sites updated (`filtersFromScope`, `assertScopeIsNonEmpty`, `scopeToCounterTuple` in threshold-reflection-policy, scope identifier formatting in core/reflection/prompt). RepoScope.repoId persists in `agent_id` column; `kind='skill'` discriminates from regular agent memories sharing the same id. **DIP discipline:** `insertSkill` / `insertDerivedSkill` / `markSuperseded` / `insertDerivedSkillAtomic` stay duck-typed on local stores (NOT on the VectorStore DIP) — matches the v0.4a `insertDerivedMemory` precedent; external adapters (REDACTED, REDACTED) not required to implement skill semantics. **OTel:** consolidate emits parent span `skills.consolidate` + 4 child spans (orient / gather / consolidate / report) with phase-level attributes when a tracer is provided. **Public exports:** `Skill`, `SkillDraft`, `SkillWithScore`, `SkillRecallOptions`, `ConsolidateOptions`, `ConsolidationResult`, `ScopedSkillMemory`, `SkillLanguage`, `SourceCluster`, `RepoScope`, `SkillRepresentation` + `SkillRepresentationStrategy` (DIP slot reserved per blueprint Rec #2 for future natural-language-spec representation), `InvalidSkillError`.
