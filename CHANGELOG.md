### Changed
- Entity linking (Phase 7) now runs on the `infer:false` verbatim write path too, via a shared `linkEntities` helper — `remember(text, { infer: false })` now extracts + surfaces entities, closing the v0.10.0 caveat (entity linking previously ran on the `infer:true` path only). Still fail-soft + `entityBoost`-gated. (#entity-extraction-nodes-slice1 fixes-cycle, item 2)


### Fixed
- Entity upsert (`PgMemoryEntityStore.upsertAndLink`) now resolves the entity id in ONE round-trip on dedup-collision via `ON CONFLICT … DO UPDATE SET name = entities.name RETURNING id` (a plain `DO NOTHING` returns no row on conflict, forcing a second `SELECT`). First-write-wins on the entity name/embedding is preserved. Perf-only; behavior unchanged. (#entity-extraction-nodes-slice1 fixes-cycle, item 3 / F-L7)
- Entity extraction no longer truncates a sentence-initial proper noun — "John Smith works at Google" now keeps "John Smith" (was dropping the leading capital), and a lone sentence-initial proper noun ("Google is a search engine") is kept, while lone sentence-initial stopwords ("Today", "I", "The") are still dropped for precision. (#entity-extraction-nodes-slice1 fixes-cycle, item 4)

## [0.10.0] - 2026-06-20

### Added
- Entity extraction (nodes) — the `entities` table is now populated from memory text on `remember()`. A new `EntityExtractor` DIP (`CompromiseEntityExtractor` default: JS-native NLP via the optional `compromise` package + regex fallback, no spaCy/Python) extracts PROPER/QUOTED/COMPOUND/NOUN nodes; a new `MemoryEntityStore` DIP (`PgMemoryEntityStore` default) persists them (deduped per `(workspace, scope, type, normalized_key)`) + links them to source memories (`memory_entities` table, migration `0018`). `GET /v1/scopes/:type/:id/entities` now serves the REAL deduplicated entities with `memory_count` + `last_seen_at` (response shape unchanged) when the read port is wired; the `attributed_to`-derived fallback is preserved otherwise. Entity linking is `entityBoost`-gated (default on) and fail-soft (a failure emits `entity_linking_failed` and never fails `remember()`). Caveat: entity linking runs on the `infer:true` write path only; the `infer:false` verbatim fast-path does not yet extract entities (follow-up). (#entity-extraction-nodes-slice1)

## [0.4.0] - 2026-06-18

### Added

- Workspace isolation completed for the secondary stores — Slice 1 is now 100% (multi-tenant-rbac-and-slice1-completion T3.1): the opt-in recall-cache, skill store, and eviction pipeline now thread `workspace_id` end-to-end. The recall-cache scope key is workspace-prefixed (`ws:<id>|<tier>:<id>`) so a byte-identical query under the same scope in two workspaces produces two distinct cache keys (no cross-workspace cache hit, EC-8). Skill `add`/`recall`/`consolidate` carry the workspace binding (a ws-A skill is invisible to a ws-B recall under the same `repoId`). The capacity + cron eviction passes scope their COUNT, candidate load, advisory lock, and nearest-neighbor isolation distance by workspace, so an eviction pass in ws-A can never soft-delete or be biased by a ws-B row. Proven by `tests/integration/workspace/cache-skill-eviction-isolation.test.ts` against real pgvector.
- Workspace RBAC management surface (multi-tenant-rbac-and-slice1-completion T2.1): a `MembersRepository` DIP (in-memory + pg impls) backs `POST/GET/PATCH/DELETE /v1/members`, gated by `requireRole('admin')` and scoped to the authenticated Principal's workspace (a cross-workspace member op is `not_found` → 404, no existence leak). The **last-owner invariant** is enforced ATOMICALLY in the pg impl (`db.transaction` + `SELECT ... FOR UPDATE` on the workspace's membership rows before the owner-count guard) so two concurrent owner-demotions can never leave a workspace with zero owners (the second serializes and returns `409 LAST_OWNER`). The admin key-mint (`POST /v1/admin/keys`) now accepts an optional `user_id` binding with an **anti-escalation guard**: minting a key bound to a member who outranks the caller is `403`, bound to a non-member is `422`, bound to a lower/equal member succeeds. Member request bodies use `.strict()` zod schemas (a forged `workspaceId` field is rejected, never silently dropped).
- Workspace RBAC roles + role resolution (multi-tenant-rbac-and-slice1-completion T0.1/T1.1): `Principal` is widened to `{ workspaceId, userId, role, scopes }` and a new `WorkspaceRole` (`owner|admin|member`) + `roleSatisfies(role, min)` ordinal-rank helper + `DEFAULT_OWNER_USER_ID` are exported from `@usetheo/memory/contract`. `ApiKeyAuthVerifier.resolvePrincipal` now LEFT JOINs `workspace_users` on `(workspace_id, user_id)` to resolve the member's role; a key with no membership row resolves to the least-privileged `member` (default-deny). The env/no-credential bridge resolves to the seeded `default-owner` with role `owner`. A new `requireRole(min)` Hono middleware + `getPrincipal(c)` helper gate management routes (401 precedes 403). The bearer middleware now FAILS CLOSED: if the auth backend throws during role resolution it returns an explicit `503 SERVICE_UNAVAILABLE` and never falls through to a privileged default Principal.
- Workspace RBAC schema (multi-tenant-rbac-and-slice1-completion T0.2): migration `0017_workspace_members.sql` adds a `users` table (global identity) and a `workspace_users` M:N membership table (`(workspace_id, user_id)` composite PK + a `role` column constrained to `owner|admin|member` by a DB CHECK), plus a nullable `theo_api_keys.user_id` FK (`ON DELETE SET NULL`) binding a key to the member it acts as. Non-destructive + idempotent: seeds a stable `default-owner` user + its `default`-workspace owner membership (`ON CONFLICT DO NOTHING`) and backfills every legacy key's `user_id` to `default-owner`, so single-tenant deployments keep working. Role resolution LEFT JOINs `workspace_users` on `(workspace_id, user_id)`; a key with no membership resolves to the least-privileged `member` (default-deny).
- Workspace isolation foundation (multi-tenant-workspace-isolation T0.1): new `Principal { workspaceId, scopes }` + `Workspace { id, name, createdAt }` domain types and a `WorkspaceMismatch` error (maps to 404), exported from `@usetheo/memory/contract`. The `AuthVerifier` DIP gains an optional `resolvePrincipal(token): Promise<Principal | null>` alongside the existing boolean `verify` (ADR D2 additive-then-breaking; becomes required and replaces `verify` in a later phase).
- Workspace isolation schema (multi-tenant-workspace-isolation T0.2): migration `0016_workspaces.sql` adds a `workspaces` tenant table (seeded with a stable-id `default` workspace) and a denormalized `workspace_id text NOT NULL DEFAULT 'default'` column on all 6 directly-queried tables (`memories`/`entities`/`history`/`consolidation_history`/`reflection_counters`/`recall_cache`) plus a `workspace_id` FK on `theo_api_keys`. Non-destructive (existing rows backfill to `default` automatically); `(workspace_id, scope)` hot-path indexes added. The `memories` dedup unique index now leads with `workspace_id` so the same fact under the same user in two workspaces is two distinct rows.
- Workspace isolation persistence (multi-tenant-workspace-isolation T1.1): the `PgvectorStore` query path now filters by `workspace_id` (composed first, ahead of the tier filter) and the insert path writes it; a new `ScopedFilters` type makes `workspace_id` a compile-time-required field on the REST/server scoping contract. Cross-workspace recall is impossible at the store layer.
- Workspace isolation auth (multi-tenant-workspace-isolation T2.1): `ApiKeyAuthVerifier` + `BearerAuthVerifier` now implement `resolvePrincipal(token)` returning the credential's `{ workspaceId, scopes }` (a revoked/expired key resolves to `null` → 401); the bearer env key bridges to the `default` workspace. The REST `bearerAuth` middleware injects the resolved `Principal` into the request context and collapses the no-credential path to the `default`-workspace Principal instead of disabling auth.
- Workspace isolation end-to-end (multi-tenant-workspace-isolation T3.1): the `Memory` contract gains `withWorkspace(workspaceId)`, returning a memory view whose every scoped operation is bound to that workspace; the REST `remember`/`recall`/`reflect`/`forget`/`scopes` handlers now derive the workspace from the authenticated Principal (never the request body) and a cross-workspace `forget` by id returns 404 without touching the other workspace's row. THE GOAL TEST (`tests/integration/auth/workspace-isolation.test.ts`) proves the IDOR matrix against real pgvector: cross-workspace recall is empty, create derives the workspace from the binding, and cross-workspace forget is a 404. README Security section documents the model + the pre-release `AuthVerifier` breaking change.


### Changed

- PRIORITY 0 scope amendment (project-owner sign-off 2026-06-17): multi-tenant-flat workspace isolation — a `workspaces` tenant boundary resolved from the API-key credential, with `AuthVerifier` evolving from a boolean check to resolving a `Principal { workspaceId }` and every query scoped by the Principal's workspace — is re-classified as IN-SCOPE under P0 as CORE to the system (foundation of the v0.5 TheoCloud runtime). The three memory tiers (User/Session/Agent) remain as within-workspace partitions; `workspace_id` is the new outer anchor. Implementation tracked under slug `multi-tenant-workspace-isolation`. See CLAUDE.md § PRIORITY 0 Amendment 2026-06-17.


### Deprecated

- `AuthVerifier.verify(token): Promise<boolean>` is soft-deprecated in favor of `resolvePrincipal(token): Promise<Principal | null>` (workspace isolation). `verify` remains during the migration window; it is removed in a later phase.



### Fixed

- Integration test suite is now deterministically green so it can gate a production deploy — closed the last 5 flaky/stale failures surfaced after the v0.3.0 release (integration-suite-stabilization). The v0.4b long-tail eviction goal test no longer collapses on pgvector's approximate HNSW index for its synthetic worst-case fixture; two CLI boot-time tests no longer false-fail on absolute wall-clock budgets under suite load (now measured relative to a cold-start baseline); the CLI warm-up-cost changelog check follows the entry to its released section instead of pinning it to `[Unreleased]`; and the `npm pack` manifest hooks no longer time out under suite load. Two consecutive keyless runs report 0 failures (494 passed, 61 skipped). No product behavior changed — test-infrastructure hardening only.
- Clarification of the v0.3.0 integration-test isolation entry: the shipped mechanism is a hybrid, not the pure "each test owns its database" design that entry described. A per-file `setupFiles` hook resets the shared `THEOMEM_PG_URI` database to a clean clone of the migrated template before each file, while the dedicated `createIsolatedDb` clone is reserved for the heavy, state-sensitive files. Both reset BEFORE the file runs, so cross-file schema-state pollution is eliminated identically. See the integration-suite-stabilization plan ADR D1-a for the rationale.


### Security

- Workspace RBAC `/review` hardening (multi-tenant-rbac-and-slice1-completion, 7-agent review): closed a BLOCKER and the HIGH findings before merge. **Minted API keys now carry the minting admin's `workspace_id`** (the key-mint INSERT previously fell back to the schema default `'default'`, cross-tenant-misplacing every credential and decoupling the anti-escalation check from the key's runtime role). Caller-role resolution in the key-mint guard is now **default-deny** (`member`, never `owner`) on a membership-lookup miss and **fails closed with 503** on auth-backend error. Key **rotation preserves** the original key's `workspace_id` + `user_id` (was dropping both → role downgrade + workspace misplacement). The opt-in skill store's `insertDerivedSkill` now writes `workspace_id` (parity with the other skill inserts — was a cross-workspace leak on the public `VectorStore` surface). `requireScope` fails closed (503) on auth-backend error. The members last-owner transaction takes a single workspace-wide `FOR UPDATE` lock (deterministic order — closes a two-different-target concurrent-demotion deadlock). `/review` verdict: `READY_TO_MERGE`. See `.claude/knowledge-base/reviews/multi-tenant-rbac-and-slice1-completion-review-2026-06-18.md`.



### Known limitation (workspace isolation follow-up)

- RESOLVED (T3.1): the opt-in recall-cache, skill, and eviction surfaces are now fully workspace-isolated (per-workspace cache key + scope-WHERE threading). The earlier deferral to `multi-tenant-workspace-isolation-secondary-stores` is closed; they are now safe to enable in a multi-workspace deployment.
- Admin key management (`/v1/admin/keys/*`, `memory:admin` scope) is deployment-level in this slice — it manages every key in the deployment, not per-workspace. Per-workspace admin delegation belongs to the deferred membership layer; treat `memory:admin` as a deployment-operator privilege.
- The `AuthVerifier` compile-time `ScopedFilters` guard (ADR D4) is a forward-looking type, not yet wired into the store signatures — isolation is runtime-enforced via the `withWorkspace` binding + the `workspace_id NOT NULL` column (proven by the IDOR goal test). Tightening the store signatures to the compile-time guard is part of the same follow-up.
